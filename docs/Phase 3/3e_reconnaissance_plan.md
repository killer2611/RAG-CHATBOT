# Phase 3E Reconnaissance Plan: Calibration & Golden-of-Goldens

## 1. Executive Summary
Phase 3E is the "Golden-of-Goldens" / Calibration phase. Its exact data contract is undefined in the repository, but existing 3D audit documents infer its role is to consume persisted benchmark artifacts and compare automated decisions against human-reviewed references. Because the live 3D pipeline currently halts at strict policy boundaries (`UnresolvedPolicyError`), 3E cannot operate on live end-to-end output. It must rely on the `ArtifactWriter` mechanism for its input, utilizing mocked/synthetic fully-resolved cases until policies are established.

## 22. AUTHORIZED INITIAL 3E CONSTRAINTS

**DECISION 1 — `claims[*].rationale`**
`claims[*].rationale` is NOT required for the initial Phase 3E implementation. Initial calibration operates on claim-level `support_status`. If reasoning traces are ever required later, persisting `ClaimVerification.reason` into `claim["rationale"]` may be considered as a separate, explicitly authorized change. Do NOT implement that change now.

**DECISION 2 — TEST INPUTS**
Initial Phase 3E tests use synthetic, hand-constructed, schema-valid BenchmarkCase fixtures. This is ONLY a testing-input constraint. It does NOT establish that synthetic data is the eventual production calibration/reference corpus. The production human-reference dataset contract remains UNKNOWN unless repository evidence establishes it.

**DECISION 3 — INITIAL CALIBRATION METRICS**
The initial Phase 3E mechanism has exactly TWO metrics:
A. Per-claim `support_status` agreement: For each comparable claim, determine whether the automated `support_status` matches the human-reference `support_status`.
B. Aggregate claim agreement: Aggregate the claim-level `support_status` agreements across comparable claims in a case.

Do NOT add precision, recall, F1, confusion matrices, retrieval metrics, case-verdict metrics, LLM-judge metrics, or additional calibration scores unless a later explicitly authorized decision requires them. CASE-LEVEL VERDICT CALIBRATION IS OUT OF SCOPE while OD #10 remains unresolved. 3E must NOT invent or infer a case-level verdict policy.

**AUTHORIZED INITIAL TEST-SCOPE MECHANICAL CONTRACT — NOT A PRODUCTION CALIBRATION POLICY.**

**CLAIM MATCHING:**
1. Initial 3E tests match claims by exact `claim_id` string equality.
2. Synthetic fixtures deliberately construct matching claim_ids on both automated and human-reference sides.
3. This is a TEST-SCOPE mechanism only.
4. Do NOT claim that claim_id is stable across production pipeline runs.
5. Production cross-run identity remains governed by unresolved OD #12.
6. Therefore exact claim_id matching must NOT be represented as a production human-reference contract.

**UNMATCHED CLAIMS:**
1. Automated claims absent from the reference are recorded as unmatched.
2. Reference claims absent from the automated case are recorded as unmatched.
3. Unmatched claims are excluded from the denominator of the INITIAL aggregate-agreement metric.
4. Duplicate claim_ids must NOT be silently resolved or deduplicated. Treat duplicates as an explicit invalid/contract-error condition in the initial mechanism unless existing repository evidence dictates otherwise. Do not invent recovery behavior.

**AGGREGATE AGREEMENT:**
For the INITIAL TEST-SCOPE metric only:

`aggregate_agreement = number_of_matched_pairs_with_equal_support_status / number_of_matched_pairs`

If zero claims match, aggregate_agreement is UNDEFINED rather than 0.

Per-claim agreement is simply:
`automated_claim.support_status == reference_claim.support_status`
